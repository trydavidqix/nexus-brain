## Canonical assimilations

### Already represented; no duplicate implementation

- Maestri Task DAG/state/policy/approval/provider/worktree/validation architecture.
- Git/agent governance and proof-gated cleanup.
- Hindsight memory/provenance/source authority.
- Engineering Control loops, independent review and verification.
- BrowserMesh.
- Capability/Provider Registry foundations and lazy tool selection.
- Workforce orchestrator/resource router.

### Newly promoted missing slice: Project Factory

Canonical flow:

OWNER OBJECTIVE -> ProjectFactoryRequest -> discovery/evidence -> capability/resource discovery -> REUSE | USE_PROVIDER | ADAPT | BUILD -> architecture decisions -> task graph -> existing Maestri + Engineering Control + Execution -> independent verification -> completion gates

Ownership:

- Maestri owns task/session/DAG lifecycle.
- Reach owns capability/provider/tool discovery.
- Engineering Control owns coding methodology and verification requirements.
- Execution owns agent/provider/runtime execution.
- Governance owns risk/approval/secret policy.
- Evidence owns proof/provenance.
- Project Factory coordinates those owners; it does not create parallel stores or routers.

This audit introduces versioned project-factory-request and project-factory-plan contracts plus validation tests. Runtime orchestration should be implemented behind these contracts and existing owners.

### Capability/Tool assimilation

Preserve progressive capability discovery, provider abstraction and health/version telemetry, implementation selection, per-task/per-agent tool profiles, Credential Broker semantics, lifecycle/evaluation data and typed outcomes/evidence. These belong inside Reach/Capability Registry/Execution/Governance rather than new Capability OS, Tool Hub or Tool Gateway products.

## Rejected from Nexus core

CRM/business workflows, social/Meta operations, commerce, phone/voice, legal department, tenant business data, hard-coded company work shifts, and emotional/personality/relationship/profanity/humanization systems are not moved into Nexus core by this audit.

## Implementation rule

Email blueprints are provenance, not authority by title. A source capability is implemented only when it has a clear Nexus owner, does not duplicate an existing authority, has contracts/acceptance evidence, is not superseded by current repository decisions, and passes tests plus independent validation.


#### Maestri Reflex / Fast Decision assimilation

The Fast Decision source is not promoted as a second router. Its useful rules are absorbed into the single `maestri.decide()` authority: deterministic facts first, confidence separate from risk, policy/approval always authoritative, and explicit abstention/fallback when evidence is conflicting or insufficient. This branch adds typed decision input/result contracts and a deterministic baseline under the Nexus control plane. Learned classification, calibration, shadow mode and training remain evidence-gated Blueprint stages.
